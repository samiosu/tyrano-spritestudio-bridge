# 検証記録

日付：2026-10-11

ティラノスクリプトV603bで、以下の5通りのブラウザ統合テストを通過しました。
スマートフォンの設定は模擬検証です。WebKitの結果を、Safari実機の確認としては扱いません。
数値の記録は [validation-results.json](validation-results.json)、再実行方法は [開発手順](DEVELOPMENT.md) にあります。

OS・GPU・ブラウザ設定が異なる環境の結果は、別途確認する必要があります。

## 全5通りで確認した動作

- プラグインタグでの読み込みとアニメーション描画、フレーム進行
- 一時停止／再開、有限再生の終了待ち、終端ポーズの保持
- 位置・拡大率・回転・透明度・表示／非表示
- 複数前景レイヤー、同じSSFBファイル名とセルマップ名を持つ別プロジェクトの青・緑の描画をピクセルで比較
- 実際の `snapSave`／`loadGameData` とmake.ksを通した復元
- 停止／一時停止状態・位置・フレームの復元、古いセーブでの表示解除、キャンバス重複なし
- 無限ループの待機・不正フレーム範囲・速度0・存在しないモーションの拒否
- スキップによる有限再生待ちの解除、削除後の再表示
- 公式の変換済みKnightメッシュ／ボーンサンプルの再生、10回のモーション変更と破棄
- 存在しないSSFB／画像に対するエラー、タグの次行進行が1回だけ行われること
- ロードでキャンセルされた再生待ちがロード先の次行を進めないこと
- `window.PIXI` を追加・変更しないこと
- READMEの6行の導入例を実行し、クリック／タッチで図形を削除して次の行へ進むこと

2種類のスマートフォン設定では、横長844×390・縦長390×844へ表示領域を変更し、
キャンバスの縦横比を維持することも確認しました。実機のOS、回転イベント、性能やブラウザUIは再現していません。

5通りとも未捕捉例外はありませんでした。
失敗する素材のテストでは、404と読み込み失敗のコンソール出力が想定どおり発生しています。
画面の確認は描画・入力の確認であり、あらゆる画面配置や端末での見た目を保証するものではありません。

## 5分間の継続試験

Chromium 154.0.8037.57で、独自デモと公式Knightデータを同じレイヤーで再生しました。
Knightの8モーションを順に使い、モーション変更、削除・再表示、一時停止・再開、位置・回転変更を繰り返しました。
20回のウォームアップ後、以下の結果を記録しました。

| 項目 | 結果 |
| --- | --- |
| 測定時間 | 300秒 |
| 反復操作 | 556回 |
| 表示全体のリセット・再構築 | 22回 |
| 実際のセーブ・ロード復元 | 11回 |
| キャンバス／プレイヤー／素材登録／描画面 | 毎回1／2／2／1を維持 |
| GC後のJavaScriptヒープ | 6,335,128 → 7,923,952バイト（約6.04 → 7.56 MiB） |
| DOMノード | 開始193、30秒以降の全測定199 |
| 未捕捉例外・検知した描画エラー | 0件 |

保持されたJavaScriptヒープの増加は1,588,824バイト（約1.52 MiB）で、
後半の測定値は約7.5〜7.6 MiBでした。増加0を確認した試験ではありません。
GPUメモリ、端末全体のメモリ、数時間のプレイは測定しておらず、この結果からメモリリークがないとは断定できません。

Knightの3つの `Setup` は、総フレーム数1に対し、出力された終了フレームが60になっています。
この3つは `start="0" end="0"` を明示し、静止ポーズとして検証しました。
残り5つのモーションは、データに記録された既定の再生区間を使用しています。

## 開発用.mjs

Node.js 20.20.2の公式Linuxコンテナで `npm run build` とユニットテスト3件が通過しました。
生成された639,227バイトの `spritestudio.js` は、既存の配布版とバイト単位で一致しました。
ゲーム側では.mjsを実行せず、通常の `[loadjs]` でこのJavaScriptを読み込みます。
ティラノスタジオ内蔵のNode.jsで開発用スクリプトを実行する試験はしていません。

## ティラノスタジオと、確認していない範囲

[公式ティラノスタジオV603](https://tyrano.jp/studio)はWindows・macOS向けです。
この環境には両OSの実行環境がなく、公式Windows版を変更せず、Wine 10.0で起動を試みました。
起動ログは出ましたが、Wineのスタックオーバーフローで異常終了し、プレビュー・書き出し操作を確認できませんでした。
これはこのWine環境の結果であり、Windows版でプラグインが動かないことを示すものではありません。

以下は未確認です。確認時の手順は [実環境の確認手順](PLATFORM-CHECKLIST.md) にまとめています。

- Windows・macOSでのブラウザ実行、Safari実機
- iOS・Android実機でのブラウザ実行、背景への移動・復帰
- ティラノスタジオ内のプレビュー、PC・スマートフォン向けの書き出しと実行
- ハードウェアGPUでの性能、GPUメモリ、数時間のプレイ
- V5、ゲーム固有のマスク・エフェクト・ブレンド、独立したインスタンスパーツの時刻
